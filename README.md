# Telegram Chat · GREEN-API

Тестовое задание на позицию React frontend developer. Простой интерфейс в стиле Telegram Web: подключение инстанса GREEN-API, создание чата по номеру, отправка и получение текста.

Задание допускает Telegram. Приложение использует **Telegram API GREEN-API**.

## Локальный запуск

Нужны Node.js **22.12+** (рекомендуется Node.js 24 LTS) и npm.

```bash
git clone <URL-этого-репозитория>
cd test_green_api
npm ci
npm run dev
```

Открыть адрес из терминала, обычно **http://127.0.0.1:5173**. Переменные окружения и собственный backend не нужны: данные подключения вводятся в интерфейсе.

```bash
npm run build       # проверка TypeScript и production-сборка в dist/
npm run preview     # просмотр production-сборки
npm test            # тесты API, обработки событий и очереди
npm run test:e2e    # браузерные сценарии на подменённых ответах API
npm run format     # форматирование исходников
```

Для браузерных тестов нужен Google Chrome. Если его нет: `npx playwright install chrome`. Playwright сам запускает dev-сервер. Скриншоты тестов сохраняются в `.artifacts/` и не добавляются в Git. Тесты не отправляют настоящие сообщения.

## Подготовка GREEN-API

1. Зарегистрироваться в [личном кабинете GREEN-API](https://console.green-api.com/).
2. Создать инстанс **Telegram** и авторизовать свой Telegram-аккаунт по инструкции кабинета. Состояние должно быть `authorized`.
3. В настройках включить `incomingWebhook` (входящие сообщения), очистить `webhookUrl` для HTTP API и сохранить изменения. Дождаться применения настроек.
4. Для статусов отправки включить `outgoingWebhook`. Для сообщений с телефона и через API можно также включить `outgoingMessageWebhook` и `outgoingAPIMessageWebhook`. Для состояния подключения — `stateWebhook`.
5. Скопировать `idInstance` и `apiTokenInstance` в форму входа. В «Настройках сервера» при необходимости указать `apiUrl` из кабинета. По умолчанию сервер определяется по первым четырём цифрам ID: `https://XXXX.api.green-api.com`.

Приложение проверяет настройки при входе, но не меняет их автоматически. Используйте одну вкладку для инстанса: другие вкладки или интеграции могут забирать события из той же очереди.

## Проверка с настоящим Telegram

1. Подключить настроенный инстанс.
2. Нажать «Новый чат», ввести номер получателя с кодом страны, например `+7 999 123-45-67`.
3. Написать текст и нажать кнопку отправки или Enter. Shift + Enter вставляет новую строку.
4. Ответить с аккаунта получателя в Telegram.
5. Убедиться, что ответ появился в том же чате.

Поиск номера зависит от приватности получателя и лимитов Telegram/тарифа GREEN-API. Если номер скрыт или аккаунт не найден, приложение показывает ошибку. Проверка формата номера не гарантирует наличие аккаунта.

## Реализация

- **React + TypeScript + Vite**, обычный CSS, иконки Lucide.
- `GetStateInstance` и `GetSettings` проверяют готовность инстанса.
- `CheckAccount` преобразует номер в Telegram `chatId` для отправки и сопоставления ответов.
- `SendMessage` отправляет `{ chatId, message }`. Ограничение — 4096 символов; пустые сообщения не отправляются.
- `ReceiveNotification` получает события последовательным long polling с таймаутом 30 секунд. После обработки и сохранения вызывается `DeleteNotification`.
- Обычный и расширенный текст отображается как текст. Вложения не отображаются, но их уведомления подтверждаются, чтобы очередь продолжала обрабатываться.
- Повторы устраняются по ID сообщения внутри чата. При сбое подтверждения повторяется только подтверждение. Временные ошибки опроса используют возрастающую задержку до 30 секунд. Ошибки доступа останавливают опрос до повторного входа.
- Часы у исходящего сообщения отображаются только во время запроса. После получения ID от `SendMessage` показывается одна галочка с подсказкой «Принято сервером. Доставка ещё не подтверждена». Это состояние не зависит от включённых исходящих уведомлений. Две галочки появляются при подтверждённой доставке; синие — при прочтении. Эти статусы обновляются по событиям API, если они включены. При неоднозначной ошибке показано «доставка неизвестна»; автоматической повторной отправки нет.
- Есть мобильная версия, поиск по созданным чатам, отдельные черновики и счётчики непрочитанных.

### Хранение данных

Токен хранится только в состоянии React и отправляется напрямую на HTTPS-сервер GREEN-API. Его нет в `localStorage`, `sessionStorage`, репозитории или логах приложения. Адрес сервера ограничен доменом GREEN-API.

Чаты сохраняются в `sessionStorage` вкладки отдельно для сервера и ID инстанса. При перезагрузке нужно повторно ввести данные доступа; переписка вкладки восстанавливается. При выходе локальная переписка удаляется. История до запуска приложения не загружается. Черновики хранятся в памяти.

Это frontend-приложение для тестового задания: владелец браузера может видеть токен в своих сетевых запросах, поскольку формат GREEN-API включает токен в URL. Сторонней аналитики нет. Шрифт Manrope поставляется с приложением и не требует внешних запросов.

### Структура

```text

  components/      # Login, NewChat, ChatApp и общие элементы

```

## Публикация

### GitHub Pages (бесплатно для публичного репозитория)

В проекте настроена автоматическая публикация через `.github/workflows/deploy-pages.yml`.

1. Открыть [Settings → Pages](https://github.com/s1lda/test_green_api/settings/pages) репозитория.
2. В разделе **Build and deployment → Source** выбрать **GitHub Actions**.
3. Отправить изменения в ветку `main`. Если они уже отправлены, открыть **Actions → Deploy to GitHub Pages → Run workflow**.
4. Дождаться успешного завершения заданий `build` и `deploy`.

После успешной публикации сайт будет доступен по адресу **https://s1lda.github.io/test_green_api/**. Последующие push в `main` автоматически обновляют сайт. Покупать домен или сервер не нужно.

Workflow устанавливает зависимости из lock-файла, запускает тесты, собирает приложение и публикует только `dist/`. В Vite настроены относительные пути ресурсов, поэтому сайт работает в подпапке репозитория. `idInstance` и `apiTokenInstance` вводятся посетителем в браузере; добавлять их в GitHub Secrets, исходники или сборку не требуется. Настройки доступа к GREEN-API остаются такими же, как при локальном запуске.

### Другой статический хостинг

`npm run build` создаёт статическую папку `dist/`, которую можно разместить на статическом хостинге. Команда сборки: `npm run build`; выходная папка: `dist`. Доступность GREEN-API из выбранного браузера и сети следует проверить на опубликованном адресе.
